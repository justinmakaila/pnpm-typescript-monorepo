## Open PR qualification

At review time [FTR PR #161](https://github.com/racedirector/ftr-events-portal/pull/161)
contains an _unmerged_, advisory public API JSDoc policy. It is **not** treated as an
accepted standard. Recently merged [FTR #160](https://github.com/racedirector/ftr-events-portal/pull/160) and [#163](https://github.com/racedirector/ftr-events-portal/pull/163) establish root import ordering and an ESLint 10 migration on FTR main; our selected ESLint 9 policy intentionally remains independent of those framework-compatibility choices. Recently merged [iRacing #510](https://github.com/racedirector/iracing-data-api/pull/510) and [#508](https://github.com/racedirector/iracing-data-api/pull/508) strengthen public JSDoc and Zod-specific lint, respectively, but their enforcement scale is not justified for an empty generic domain. Other open PRs primarily concern application-specific execution/authentication. The current
`main` snapshots above remain the implementation authority.

## Consequential tradeoffs

1. **ESLint 9 rather than 10:** avoids importing FTR's then-current compatibility shims;
   useful core rules are centralized, and custom enforcement is tested. Upgrade when
   framework plugins actually used by a consumer support it.
2. **NodeNext only for Node examples:** a browser app may use `Bundler`; no universal
   resolver forces incompatible environments into one output mode.
3. **Manifest-driven custom checker rather than elaborate boundary plugins:** the
   starter has two packages, so explicit import/manifest integrity is auditable; retain
   ESLint for everyday import quality.
4. **No project references:** pnpm topological build plus compiled public exports are
   sufficient. Add TS build mode when a larger graph proves it useful.
5. **No release framework or infrastructure:** private packages are the safe default;
   optional publishing is an independent decision, not an automatic side effect.
